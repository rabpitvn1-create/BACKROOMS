Backroom 1.1.37

Item-state and warning feedback update.

- Introduces a deterministic three-state consumable model for supported resource items: FULL -> LOW -> EMPTY, without ml/gram/percentage simulation.
- Keeps empty containers and other persistent physical objects instead of deleting them on USE.
- Separates stack variants by gameplay state, so full, low and empty items remain distinct inventory stacks.
- Preserves Omnivault Scan/Copy behavior and requires an actual available object or scan template.
- Rejects unsupported precise content amounts such as 200 ml, 50% or half-full states.
- Standardizes invalid deterministic gameplay feedback with a visible [Warning] prefix.
- Uses the player-facing Scan/Multiply warning: "There is no object available for scanning or multiplying."
- Adds warning styling in the game log so rejected commands are visually distinct from Game Master narrative.
- Retains the deterministic Kotlin Game State Core, LiteRT classifier and Gemini fallback pipeline.
