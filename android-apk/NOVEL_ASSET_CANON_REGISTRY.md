# Novel/Asset Canon Registry

## Scope and authority

This registry covers **11 approved source documents** from [Novel/Asset](https://drive.google.com/drive/folders/1tVcjppBYNI90VSfQ3JFq870xkJ8laqSo). It does not declare that every piece of historical prose is an event in the active campaign.

The order of authority is:

1. Latest explicit instruction and approved continuity retcon.
2. Current campaign state and `android-apk/cao-minh-prologue.txt`.
3. Current Codex belonging to the character being described.
4. Current Backrooms world, Entity, and mechanism canon.
5. Historical narrative material and purely visual references.

If a source conflicts with a newer campaign retcon, preserve the original citation but apply the current continuity; do **not** restore retired arrival/reunion stories from the original Drive copies.

## Data contract and operational flow

Authoritative document inventory: `app/src/main/assets/knowledge/novel_asset/manifest.json` (schema v2).

Each manifest document declares:

- `name`, `driveId`, `path`, `policy`: provenance and authority.
- `topics`: explicit normalized aliases for *on-demand* knowledge selection, not character knowledge.
- `gate`: `contextual` or `after_first_contact`.

The full source text is stored in `app/src/main/assets/knowledge/novel_asset/`. The deterministic indexer produces records in `app/src/main/assets/knowledge/knowledge_db.json`. A record contains `id`, `domain`, `kind`, `text`, `source.document` and `source.anchor`, `authority`, `mutability`, `priority`, `tags`, `references`, and `affordances`. Stable chunk IDs use `NOVEL_ASSET.<SOURCE_STEM>.C####`.

The runtime retrieval implementation is generated by `patch-knowledge-engine-source.py`, invoked by the existing Android release patch chain. **Do not patch the checked-in `KnowledgeContextEngine.kt` in isolation**: that will diverge from the compiled APK. The generated `addNovelAssetExcerpts()` implementation uses `novel_topic:` aliases from the database and the `novel_gate:after_first_contact` tag for Trác Lâm. Context selection is bounded to three matched documents and an existing token budget; importing 277 indexed excerpts never means supplying all excerpts to the model.

Current registry inventory: **11 documents, 288 indexed full-text excerpts**. The preexisting non-Novel registry records are preserved.

## Prevent narrative leaks and authority inversion

- `WRITER_SECRET` is guidance to the story writer, never evidence a character has discovered that history.
- `VISUAL_REFERENCE` cannot supersede the Entity state machine, rules or spawn probabilities.
- Character Codex establishes identity and capability, but current presence, health, equipment state, discoveries and social relationships remain controlled by validated game state.
- Trác Lâm's Codex cannot be selected before first contact solely because the player types his name. The first-contact event itself must be validated by active continuity.
- The GM cannot invent missing facts, prematurely reunite separated characters, grant backstage knowledge, or make a character incompetent to preserve suspense.
- The manifest's `topics` are intentionally constrained; adding a broad synonym can leak unrelated historical prose.

## Verification and updating

After modifying an approved source, update its reviewed copy, manifest and deterministic knowledge index *together*. Preserve the original `source.document` and the current campaign's retcon precedence.

1. `python3 android-apk/build-novel-asset-canon-index.py --write` to regenerate.
2. `python3 android-apk/build-novel-asset-canon-index.py --check` to confirm deterministic indexing.
3. Run the production Android patch chain before `gradle -p android-apk :app:testDebugUnitTest :app:assembleDebug --no-daemon`.
4. `python3 android-apk/verify-novel-asset-apk.py android-apk/app/build/outputs/apk/debug/app-debug.apk` to compare all approved source bytes and index chunks in the *actual built APK*.
5. Wait for GitHub Actions **GREEN** before merging; APK packaging is not the same as correct runtime retrieval.

The isolated CI workflow `.github/workflows/verify-novel-asset-canon.yml` executes these checks for this integration.
