# Level 0 MAP / Player Action / GM fixes — 2026-10-19

Baseline: PR #654, `6bdee25172d0889ed1126c8fd4cfe773b0a71f18`.
Evidence: `Backroom-Diagnostic-20261019-172110.json`, app 1.2.0.0.38 / code 111. The diagnostic is evidence, not a save to import.

## Verified causes

- MAP used BFS depth rows plus straight lines over all 45 rooms. It ignored the existing Canon parent/zone membership, making cross-cluster links and loops hard to follow.
- FREE-only player entries were appended only after a successful writer response. Writer failure therefore lost the visible utterance. Mixed/Core batches relied on folding receipt rows in a client projection; the final combined narration and recovery events were not a durable native batch.
- Writer failure left short Core receipt text under GAME MASTER. This explains the diagnostic's final 67-character response; it does not prove that the provider itself wrote a short valid answer.
- The mixed prompt serialized the entire client state, including a 33,700-character prologue and the growing transcript. Diagnostic prompts were 75,493–84,982 characters. Scene narration used a 2,048-token output budget and presentation flattened all whitespace.
- Diagnostics recorded only exception classes. The exact throwing validator for the historical `IllegalArgumentException` cannot be recovered from this file. `SocketException` is a distinct transport failure. Neither class establishes that all observed quality differences are network-related.

## Changes

- Core publishes opaque visual cluster IDs, hub flags, public cluster labels and confirmed one-way edge metadata. It does not modify seeded topology, secret-passage discovery, unlock predicates or puzzle state.
- MAP groups rooms by Core membership, follows actual local adjacency, searches the eight-cluster ordering, routes orthogonal paths around cards with bend/congestion costs, and highlights incident edges on selection. The full graph opens at native scale and remains pan/scrollable; manual zoom is described below. Header, exact environment snapshot, dimmed nameless locked nodes, dashed edges and gold map-motif pin remain. Missing image identity does not substitute a different area's image. An open MAP updates/recenters after a Core turn.
- The latest utterance and its public event journal are stored as presentation-only data in `GameState.world`. The player line exists before the planner request. A Core event and its receipt ID join the journal in the same repository save as the Core commit. FREE acceptance changes only presentation; no inventory/time/RNG/encounter/puzzle effect.
- Projection upserts one player and one response by request/receipt identity. Pending direct choices also keep their player line on writer failure. Factual interim text is labeled CORE, not GAME MASTER. Original player text and paragraph breaks survive. An unchanged draft retried after a zero-step planner failure reuses its request identity; editing the draft starts a new turn.
- Narration retry reads the persisted resolved events, invokes no planner and never replays committed commands. An actually pending Core command retains its existing one-shot reservation and may commit once before recovering the batch narration. Remaining unexecuted steps require a new deliberate instruction.
- Mixed GM state is an allow-list plus at most four recent entries / 4,500 characters of chronological context. The full reader novel, atlas, map, puzzle controls and record collections are excluded. A separate 6,887-character historical opening context is appended to both writer paths outside the recent-history limit. Current public events remain complete. Direct scene GM input also drops the visual map.
- Writer validation classifies transport/timeout, HTTP, envelope/finish, truncated, filtered, empty, JSON/schema and code-owned content errors without logging raw bodies, keys or prompts. Valid short replies remain valid. The narration budget is 4,096 tokens, with no fixed prose minimum and no silent success fallback.
- The active narrative policy now requires intent → observed action → confirmed result, grounded environmental detail, variable pacing, no repetitive introductions, and no invented official evidence/puzzle completion.
- For this PR branch, existing CI runs the focused map/presentation/provider/projection/puzzle/checkpoint regression gate once and builds one debug APK. Duplicate broad test execution and the unrelated Canon trial APK are skipped; superseded builds on this branch are cancelled. No Android Emulator job is enabled.

## Follow-up: one-time PROLOGUE and MAP zoom

Baseline: `30128498f801dfcfa3edafd94c6453111bf9dbcc`, same PR/branch.

- The earlier Prologue used a persistent `<details>` row in a four-row game grid, had no dismissal lifecycle and could remain in the main UI. It is now an absolute, full-width rounded gold/brown offer with centered **PROLOGUE** and a separate X. Reading opens the original full text in a scrollable native dialog and consumes the offer. X consumes it without loading the novel. Closing/escaping the reader, rendering, reloading or restoring a checkpoint does not resurrect a consumed offer. A successful New Game resets the offer and closes GAME MENU to show it immediately; a rejected Core reset preserves the current choice and state. The choice is a separate UI localStorage key, outside Core and checkpoint data. If localStorage is unavailable it still works during the current session, but cannot persist across restart.

Wheel zoom anchors at the cursor; two-finger pinch anchors at the moving midpoint; button zoom anchors at viewport center. The SVG viewBox/topology stays unchanged while its physical dimensions and scroll extents scale together. One-finger/mouse pan remains available; drag/pinch does not accidentally select a node. Default opening remains 100% centered on Cao Minh.
