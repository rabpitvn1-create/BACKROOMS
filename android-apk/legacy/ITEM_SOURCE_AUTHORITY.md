# Legacy item sources

Active runtime item acquisition is intentionally restricted to exactly two authoritative origins:

- `ENTITY`: deterministic Entity drop / overflow drop generated by combat code.
- `CHEST`: an item already present in authoritative Chest contents. Every Chest item must carry a stable `chestId`.

The following former acquisition paths are retired and must not create active Inventory items:

- GM / Gemini `inventory_upsert`.
- Story-granted or narration-granted items.
- Generic `loot` roll creating loose items.
- `WORLD` loose-item pickup without Entity/Chest provenance.
- Candidate inventory snapshot diffs.
- Any other runtime source that cannot prove `ENTITY` or `CHEST`.

Old `flags.worldItems` entries from those retired sources are quarantined to `flags.legacyWorldItems` with `legacyReason=retired_item_source`. They are retained only for save compatibility/debugging and are ignored by active pickup resolution.

Chest item ledger contract:

```json
{
  "id": "item-id",
  "name": "Item Name",
  "quantity": 1,
  "available": true,
  "metadata": {
    "itemOrigin": "CHEST",
    "chestId": "stable-chest-id"
  }
}
```

Entity overflow items use the same `flags.worldItems` ledger but keep `metadata.itemOrigin=ENTITY`.

Omnivault storage/withdraw/copy is not an independent world spawn source: it operates only on items/templates already present in authoritative state. Canonical starting equipment remains initialization, not runtime acquisition.
